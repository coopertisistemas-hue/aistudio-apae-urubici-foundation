# W01P — Proposal Site Mode

## Purpose

Allow the APAE Urubici Public Site to be designed and implemented as a high-quality proposal/demo before the institutional validation meeting.

This is a controlled exception to the normal sequence W01 → W02 → Readdy.

The objective is to present APAE Urubici with a tangible premium digital proposal, not to publish unvalidated institutional facts.

## Scope

W01P authorizes:

- Public Site visual implementation;
- responsive/mobile-first layout;
- premium homepage composition;
- internal page shells;
- provisional design system;
- proposal-grade hero;
- projects/campaign/testimonial/partner presentation patterns;
- transparency page structure;
- donation UX concept;
- Portal Urubici editorial section concept;
- accessibility behavior;
- SEO-ready semantic structure.

W01P does NOT authorize:

- production certification;
- publishing unvalidated APAE facts;
- real payment processing;
- real donor data;
- real CRM capture unless explicitly approved;
- production Admin implementation;
- production Supabase/RLS/payment contracts;
- publishing sensitive media without rights validation.

## Proposal content rule

Where institutional data has not been validated:

1. Prefer generic, structurally meaningful proposal copy.
2. Use labels such as "Conteúdo a validar com a APAE" only in internal/admin/demo contexts when needed.
3. Do not present fabricated statistics, names, services, partner claims or beneficiary stories as fact.
4. Avoid visible lorem ipsum where polished proposal copy can express the intended experience safely.
5. Any public-looking demo data must be obviously generic and non-factual.

## Visual authority

During W01P, Readdy may make reversible visual choices only within the approved Foundation principles.

It may:
- propose a provisional palette derived respectfully from APAE identity;
- propose typography;
- propose spacing, component and layout treatments.

It must not:
- declare those choices final;
- overwrite Foundation design principles;
- introduce arbitrary brand directions inconsistent with APAE identity;
- encode provisional choices as institutional brand truth.

All proposal visual choices are subject to W02 finalization after stakeholder feedback.

## Hero

The proposal should demonstrate the intended premium hero experience.

If approved real APAE video is not yet available:
- use a neutral/reversible proposal asset;
- or a static premium fallback;
- do not use identifiable beneficiary/minor imagery without authorization;
- preserve the final data model for separate desktop/mobile media and posters.

## Data behavior

The proposal may use local/mock/provisional data structures for presentation.

However:
- data models must remain compatible with the Foundation;
- mock data must be isolated and easy to replace;
- no mock content may be mistaken for production data;
- no privileged backend integration is required for W01P.

## Presentation objective

The proposal should help APAE leadership react to:
- visual direction;
- homepage hierarchy;
- information architecture;
- partner recognition;
- donation concept;
- testimonials concept;
- transparency;
- Portal editorial integration;
- Urubici Connect technology-partner positioning.

## Release status

A W01P Site may be:
- locally previewed;
- deployed to a clearly non-production proposal/staging URL;
- shown in a meeting.

It must not be represented as the official production APAE Urubici website.

## Exit

After stakeholder presentation:

- approved choices move into W01/W02 validation;
- rejected visual/content concepts are revised;
- institutional facts are validated;
- Site proposal is hardened into production candidate only after the required gates.
